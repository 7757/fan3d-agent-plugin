# Screen copy and audio

Read this reference when the introduction uses device-screen media, directional
copy, background music, or the original audio from a screen video.

## Build the message from product truth

- Give each shot one communication job: establish the product, demonstrate one
  benefit, show evidence, or close with the intended next step.
- Prefer short, concrete copy that names what the viewer can see. Do not invent
  product claims, metrics, customer quotes, platform support, or availability.
- Distinguish pixels inside the supplied screen asset from Fan3D directional
  labels. Use labels for brief supporting copy; use a prepared image or video
  when the screen itself needs a designed UI state, caption, or sequence.
- Read the installed font catalog before choosing label typography. Preserve
  inspected label text, style, and placement that the user did not ask to
  replace.

## Install and frame screen media

- Inspect the target device, screen slot, current media identity, orientation,
  and presentation mode before editing.
- Import an image or video only from an absolute local `file:` URL explicitly
  supplied by the user or calling client for this task. Never search for, guess,
  enumerate, or silently reuse a local file.
- Choose orientation and fit, fill, or stretch from the live tool schema. Check
  representative previews for cropping, letterboxing, legibility, and correct
  device orientation.
- A device-screen video starts at project time zero. Source trimming is
  reversible, but it cannot delay the video's project start or create an empty
  lead-in. If the story needs a later screen-video cue, reveal it with the
  available camera or scene timing, prepare a different source asset, or mark
  the cue for post-production.
- Do not claim that Fan3D edited the pixels, captions, or internal cuts of a
  supplied screen asset unless a published tool actually performed that work.

## Keep the audio roles separate

- Device-screen original audio and project background music are independent.
  Inspect and change each track explicitly; muting one must not be described as
  muting the other.
- Screen-video volume is bounded from silence to its original level. Do not
  promise amplification, normalization, ducking, or mixing that the live tools
  do not expose.
- Discover bundled music and the managed user library through their live
  catalogs. Choose only from returned metadata and stable identities; do not
  hard-code tracks or claim to have auditioned audio without an actual listening
  capability.
- Import local music only from an explicitly supplied absolute `file:` URL.
  Narration, voice generation, sound-effect design, multi-track mixing, and
  editorial music cuts require prepared source media or post-production unless
  the current server publishes a specific capability for them.
- Still images and image sequences do not carry audio. Confirm the intended
  audible state for a movie separately from visual preview review.
